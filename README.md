# Group Call Bot

Минималистичный Telegram-бот для групп: по команде администратора периодически
упоминает участников **текущего чата**. Рядом в том же процессе поднимается
Flask-сервер (`GET /` → `Hello World`).

## Команды

| Команда | Описание |
|---|---|

| `/start` | краткая инструкция |
| `/startcall <интервал>` | запустить цикл, например `/startcall 10m` |
| `/stopcall` | остановить цикл в этой группе |
| `/call` | один цикл упоминаний прямо сейчас |

Интервал: число + `s`/`m`/`h` — `/startcall 30s`, `/startcall 5m`, `/startcall 2h`,
минимум — `/startcall 1s`, максимум 24 часа. Управление доступно только
администраторам группы (включая анонимных админов).

Каждая группа независима: `chat_id → интервал + asyncio.Task`. Повторный
`/startcall` отменяет старую задачу и запускает новую.

## Известные участники ≠ полный состав группы

Это два разных понятия, и бот не подменяет одно другим:

* **Полный состав группы** — Bot API умеет возвращать только *число* участников
  (`getChatMemberCount`) и данные одного конкретного пользователя
  (`getChatMember`). Число показывается при `/startcall`.
* **Известные участники** (`known_members[chat_id][user_id] = user`) — те,
  кого бот реально увидел в апдейтах: авторы сообщений, вошедшие
  (`new_chat_members`), авторы закреплённых и пересланных сообщений. Запись
  обновляется при каждом новом событии; по таймауту «за молчание» никто не
  удаляется, уходят только реально покинувшие чат (`left_chat_member`).

Сообщения бота всегда честно называют их: `📣 Зову известных участников (2): ...`
и `Цикл запущен: упоминания каждые 10 с. Известных участников: 2.`

## Почему нельзя получить полный список через Bot API

В Telegram Bot API **нет метода перечисления участников** ни для обычных групп,
ни для супергрупп — ни с правами админа, ни без. Единственные связанные методы:
`getChatMemberCount` (только количество) и `getChatMember(user_id)` (один
известный id). Полный roster доступен только MTProto-клиентам (пользовательский
API с api_id/api_hash), но это уже не Bot API; использовать userbot-обход бот
сознательно не делает. Поэтому единственная честная стратегия для бота —
копить участников из потока обновлений в RAM и явно сообщать об этом ограничении.

## Упоминания

* известные участники разбиваются на сообщения по 5 человек (17 → 5+5+5+2);
* если есть `@username` — обычный текст, иначе настоящий HTML-mention через
  `tg://user?id=...`;
* между сообщениями пауза ~1.5 с; при `RetryAfter`/FloodWait бот ждёт указанное
  время и делает одну повторную попытку (без агрессивных ретраев). Даже при
  `/startcall 1s` отправка идёт с учётом rate limits.

## Запуск

```bash
pip install -r requirements.txt

export BOT_TOKEN="123456:ABC..."   # токен от @BotFather
export PORT=8080                   # опционально, по умолчанию 8080

python main.py
```

Бот работает в группах; добавьте его в чат и дайте право отправлять сообщения.
В личке доступны только `/start`.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен бота (обязательно) |
| `PORT` | порт Flask (по умолчанию 8080) |

## Ограничения RunXBuild

Постоянного хранилища нет, поэтому:

* без SQLite / Redis / PostgreSQL / локальных файлов состояния;
* таймеры и известные участники живут в RAM и сбрасываются после перезапуска —
  это ожидаемое поведение;
* бот не пишет пользователям в личку, только в тот чат, где вызвана команда.
